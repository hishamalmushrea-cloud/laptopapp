# خارطة الطريق / Roadmap

مرتّبة حسب **الأثر ÷ الجهد**. البنود 1–2 أساسية قبل أي ميزة.

## المرحلة 0 — الثقة (لا ميزات جديدة قبلها)

### 1. CI + بصمات + توقيع
- [x] `scripts/fetch-assets.sh` يتحقق من SHA-256 لكل ملف ثنائي (73 ملفًا).
- [x] `ci/build.yml` مكتوب ومختبَر الصيغة (وظيفتان: `assets` ثم `apk` مع نشر `SHA256SUMS.txt`).
- [ ] **تفعيله**: `scripts/install-ci.sh` ثم push بتوكن يملك صلاحية `workflows`
      (التوكن الآلي الحالي لا يملكها — GitHub رفض الـ push صراحةً).
- [ ] إضافة `assembleRelease` موقّع على كل وسم.
- [ ] *لماذا أولًا:* upstream بلا أي CI، وAPK بحجم ~150 MB يُبنى يدويًا، ونسخ "معدّلة"
      منتشرة. هذه أرخص طريقة لإغلاق أخطر ثغرة ثقة.

### 2. اختبارات لل منطق القابل للاختبار
- [ ] نقطة بداية واقعية (بلا أدوات محاكاة): `GraphicsDrivers.parseIdentifiers/parseConfigs`,
      `DefaultVersion.DXVK(...)`, `KeyValueSet` — منطق نصّي خالص، مثالي لـ JUnit.
- [ ] لا يوجد حاليًا أي `test/` أو `androidTest/` ولا تبعية junit (تحقّقنا).

## المرحلة 2 — البنية

- [ ] **رفع `targetSdkVersion` عن 28.** حاليًا `targetSdk 28` مع `compileSdk 35` —
      هذا يمنع التوزيع عبر المتاجر ويرث `WRITE_EXTERNAL_STORAGE`. المسار: تنفيذ الملفات
      الثنائية من مجلد المكتبات الأصليّة داخل APK بدل مجلد البيانات.
- [ ] **تحديث تفاضلي / تنزيل المكوّنات عند الطلب** بدل إعادة تنزيل ~150 MB كل مرة.
      الأساس موجود: ميزة "تثبيت مكوّنات من ملف" في 11.0.
- [ ] `minifyEnabled true` في debug → تعطيله (يبطئ التطوير).
- [ ] إضافة `signingConfig` لـ release.
